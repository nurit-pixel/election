# ליל המדגמים

משחק ניחושים חברתי לבחירות לכנסת ה-26 (27.10.2026): כל אחד ממלא הימור אחד, ומשחק מול חברים בקבוצות פרטיות או פתוחות. Next.js 15 + Supabase, פריסה ב-Railway. על נקודות בלבד, בלי כסף.

(התחיל כ"מטה המאבק כוח 43" — המשחק המשרדי, שהפך לקבוצה הראשונה.)

## הרצה מקומית

```bash
npm install
cp .env.example .env.local   # ולמלא ערכים
npm run dev                  # http://localhost:3000
npm test                     # בדיקות הניקוד (vitest)
npm run lint                 # typecheck
```

## משתני סביבה

| משתנה | תיאור |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | כתובת פרויקט ה-Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key (בפועל כל הטבלאות חסומות ל-anon) |
| `SUPABASE_SERVICE_ROLE_KEY` | service role key — **רק בשרת**, אף פעם לא עם `NEXT_PUBLIC_` |
| `SESSION_SECRET` | אופציונלי. מפתח לחתימת ה-cookie של השחקנים (ברירת מחדל: ה-service role key). החלפה שלו מנתקת את כל השחקנים |
| `ADMIN_CODE` | קוד חדר המצב (`/admin`) |
| `LOCK_AT` | מועד נעילת הטופס (ISO). ברירת מחדל `2026-10-27T22:00:00+03:00` — ראו הערה ב-`NOTES.md` על שעון החורף |

## הקמת Supabase

1. פרויקט חדש ב-supabase.com.
2. SQL Editor → להריץ את `supabase/migrations/001_init.sql` (או `supabase db push` עם ה-CLI).
3. Settings → API: להעתיק את ה-URL, ה-anon key וה-service role key למשתני הסביבה.

## פריסה ל-Vercel

1. Import של הריפו ב-Vercel (Framework: Next.js, בלי הגדרות מיוחדות).
2. Settings → Environment Variables: להגדיר את כל המשתנים שלמעלה (Production + Preview).
3. Deploy. אחרי שינוי משתני סביבה צריך Redeploy.

## פריסה ל-Railway

1. railway.com ← New Project ← Deploy from GitHub repo ← `nurit-pixel/election`.
2. בשירות שנוצר ← Variables: להגדיר את משתני הסביבה שלמעלה (Supabase ×3, `ADMIN_CODE`, ואופציונלית `LOCK_AT`, `SESSION_SECRET`).
3. Settings ← Networking ← Generate Domain, כדי לקבל כתובת ציבורית.
4. ההגדרות לבנייה ולהרצה נמצאות ב-`railway.json` (build: `npm run build`, start: `npm start` על `$PORT`, בדיקת חיים ב-`/api/health`).

> משתני `NEXT_PUBLIC_*` נכנסים לקוד בזמן הבנייה. אם משנים אותם, צריך Redeploy.

## מד הסלמה ישראל–איראן (`/iran`)

מחשבון סבירות לחזרה לאש ישירה בין ישראל לאיראן: אינדיקטורים, הצהרות מנהיגים, יומן ידיעות, סקרים, בורסה, דלק ושווקי הימורים. דף סטטי אחד שאפשר להתקין כאפליקציה (PWA) ועובד גם בלי חיבור.

- `public/iran/index.html` — כל הדף: הנתונים (`IND`, `NEWS`, `FIN`, `POLLS`) והחישוב. עדכון ערכים = עריכת המערכים האלה ופריסה מחדש. מה שהמשתמש משנה נשמר רק בדפדפן שלו.
- `app/api/iran/markets` — מושך שווקים פתוחים על איראן מ-Polymarket (מטמון 10 דקות) ומציג אותם בדף עם כפתור "הוסף לחישוב". אם Polymarket לא זמין, הדף ממשיך לעבוד עם הזנה ידנית.
- `public/iran/sw.js`, `manifest.webmanifest`, אייקונים — התקנה למסך הבית ועבודה אופליין.
- הניתוב `/iran` → `/iran/index.html` מוגדר ב-`next.config.ts`.

### עדכון חי כל שעה

השרת מריץ סבב עדכון פעם בשעה (מתזמן פנימי ב-`instrumentation.ts`, שבודק כל 5 דקות):

1. **איסוף** (`lib/iran/feeds.ts`): כותרות מ-Google News בעברית ובאנגלית, ynet ו-Times of Israel; מחירי ברנט, WTI, דולר/שקל, ת"א 35, אלביט וזהב מ-Yahoo Finance; שווקים פתוחים מ-Polymarket.
2. **הערכה** (`lib/iran/assess.ts`): Claude קורא את הכותרות ואת ערכי האינדיקטורים, ומחזיר שינויים, תיאור מצב מעודכן וידיעות ליומן. הגנות: לכל היותר צעד אחד לשעה לכל אינדיקטור, רק מזהים מוכרים, וידיעה נכנסת ליומן רק עם קישור מהכותרות שנאספו.
3. **שמירה** (`lib/iran/store.ts`): תמונת מצב בטבלה `iran_snapshots`. צריך להריץ את `supabase/migrations/004_iran_snapshots.sql`. בלי Supabase הנתונים נשמרים רק בזיכרון ומתאפסים בכל פריסה.
4. **הדף** טוען את `/api/iran/state` כל 5 דקות, מציג שעון עצר לעדכון הבא, גרף מגמה וסיכום. ערך שהמשתמש הזיז ידנית לא נדרס.

משתני סביבה:

| משתנה | תיאור |
|---|---|
| `ANTHROPIC_API_KEY` | נדרש להערכה האוטומטית. בלעדיו מתעדכנים רק מחירים ושווקים |
| `IRAN_CRON_SECRET` | אופציונלי. מאפשר להפעיל סבב ידנית: `curl -X POST -H "x-cron-secret: ..." https://<domain>/api/iran/refresh` |
| `IRAN_MODEL` | אופציונלי. ברירת מחדל `claude-opus-5-5` |
| `IRAN_AUTO_REFRESH` | `off` מכבה את המתזמן הפנימי (למשל אם מפעילים cron חיצוני) |

עלות משוערת: קריאה אחת ל-Claude בשעה, כ-24 ביום.

## החלפת קריקטורות

כל מפלגה מוצגת מ-`public/caricatures/<key>.png` (ריבוע 400×400, רקע שקוף). כל עוד אין PNG, מוצג ה-placeholder `public/caricatures/<key>.svg` (עיגול בצבע המפלגה עם אות הפתק).

כדי להחליף: לשים קובץ `likud.png` (וכו') ב-`public/caricatures/` ולפרוס מחדש. אין צורך לשנות קוד. ה-`key` של כל מפלגה נמצא ב-`lib/parties.ts`.
אחרי שינוי אותיות או צבעים ב-`lib/parties.ts` אפשר לייצר את ה-placeholders מחדש: `npx tsx scripts/gen-placeholders.ts`.

## ליל הבחירות — הזנת תוצאות

1. להיכנס ל-`/admin` עם `ADMIN_CODE`.
2. **22:00 — הטופס ננעל אוטומטית** לפי `LOCK_AT`. אפשר גם ללחוץ "נעל טופס" ידנית (או "פתח טופס" אם צריך הארכה; "חזרה לנעילה אוטומטית" מבטל את הדריסה).
3. **מדגמים:** להזין מנדטים לכל מפלגה (0 = לא עברה), רה"מ/גוש/בונוסים אם כבר ידועים (אחרת "עוד לא ידוע" — לא מקבלים עליהם נקודות), לבחור מצב **מדגמים** → "שמור וחשב ניקוד". הלוח יציג דירוג ביניים עם התווית "לפי מדגמים — לא סופי".
4. **כל עדכון:** לשנות ערכים → "שמור וחשב ניקוד". הלוח מתרענן אצל כולם כל 60 שניות.
5. **תוצאות רשמיות:** להזין את הכל, לבחור מצב **רשמי** → "שמור וחשב ניקוד".
6. "ייצוא CSV" מוריד את כל ההימורים והניקוד (נפתח באקסל עם עברית תקינה).

> הניקוד מחושב אוטומטית בכל שמירה. התוצאות עצמן מוזנות ידנית — אין משיכה אוטומטית ממקור חיצוני.

## ניהול שחקנים

בחדר המצב ← לשונית **שחקנים**: רשימת כל המגויסים (מי הגיש, מתי עודכן, ניקוד), חיפוש, ולכל שחקן:
- **שינוי שם** — למשל לתיקון שגיאת כתיב או כפילות.
- **איפוס** — מוחק את ההימור והניקוד; השחקן נשאר ויכול למלא מחדש (עד הנעילה).
- **מחיקה** — מוחק את השחקן לגמרי, כולל ההימור והניקוד. אי אפשר לבטל.

## היסטוריית הגשות

כל שליחה של "סגור את הפתק" נשמרת. השחקן רואה את ההיסטוריה שלו בדף האישור ("היסטוריית ההגשות שלי"), ובחדר המצב ← שחקנים ← **היסטוריה** רואים אותה לכל שחקן. בכל הגשה מוצג מה השתנה לעומת הקודמת, ולחיצה מציגה את ההימור המלא באותו רגע.

**הפעלה חד-פעמית:** ב-Supabase ← SQL Editor ← להריץ את `supabase/migrations/002_bet_history.sql`. ההימורים הקיימים נכנסים אוטומטית כהגשה הראשונה. עד שמריצים — הכל עובד כרגיל, רק בלי היסטוריה. בטוח להריץ יותר מפעם אחת.

## משתמשים וקבוצות

- **כניסה:** שם משתמש ייחודי + קוד אישי בן 4 ספרות (נשמר מוצפן). 5 טעויות → חסימה ל-15 דקות. שחקנים ותיקים בלי קוד בוחרים קוד בכניסה הבאה. שכחו קוד? חדר המצב ← שחקנים ← **איפוס קוד**.
- **הימור אחד** לכל משתמש, שנספר בכל הקבוצות שלו.
- **קבוצות:** כל משתמש יכול לפתוח קבוצה (שם, אימוג'י, צבע, פרטית/פתוחה) ולשלוח קישור `/g/<קוד>`. פתוחות מופיעות לכולם ב"הקבוצות שלי".
- **מנהל/ת קבוצה:** הזמנה, עריכת הגדרות, הסרת משתתפים, מחיקת הקבוצה, ועד 5 **שאלות בונוס משלה** (עד הנעילה) + הזנת התשובות הנכונות. אם יש לקבוצה שאלות — הן מחליפות בה את 5 שאלות הבונוס הכלליות.
- **אדמין ראשי** (`/admin`): תוצאות לכולם, שחקנים, וכל הקבוצות (כולל מחיקה). יכול גם לנהל כל קבוצה.

**הפעלה:** להריץ ב-Supabase את `supabase/migrations/003_groups.sql` **לפני** פריסת הקוד. היא יוצרת את הטבלאות ומעבירה את כל השחקנים הקיימים לקבוצה "מטה המאבק כוח 43" (קוד `koach43`), בניהול של נורית. בטוח להריץ שוב.
