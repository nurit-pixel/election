# פראיירמטר

אפליקציית ווב משפחתית (עברית, RTL, mobile-first) להשוואת מחירי סל קניות בין סניפי סופרמרקטים,
על בסיס קבצי שקיפות המחירים שהרשתות מפרסמות לפי חוק קידום התחרות בענפי המזון והפארם.

הפרויקט נמצא בתיקייה `supermarket/` ועצמאי לגמרי משאר המאגר.

## מצב נוכחי: כל שבעת השלבים

- כל הרשתות (33 מקורות): רשימת סניפים ארצית, geocoding עם cache, ומחירים ומבצעים לסניפים שברדיוס הכתובות השמורות.
- **הרשימה שלי:** הוספת מוצרים בחיפוש לפי שם או בסריקת ברקוד, כמויות (ק״ג למוצר שקיל), וקבוצות חלופות.
- **השוואת סניפים:** דירוג הסניפים שברדיוס לפי מחיר הסל אחרי מבצעים. סניף שחסרים בו פריטים מסומן "נמצאו X מתוך Y" ומופיע אחרי הסלים המלאים. רשתות פארם לא בדירוג.
- **פירוט סניף:** המוצר שנבחר לכל פריט, מחיר, המבצע שחל, חיסכון אפשרי לחברי מועדון, מבצעים שלא חושבו, ומה חסר.
- **פיצול לשני סניפים:** כל הזוגות מבין עד 20 הסניפים הקרובים, כל פריט בסניף שבו הוא זול יותר (`web/lib/split.ts`). מוצג רק כשהחיסכון לעומת הסל הזול בסניף אחד עובר סף (ברירת מחדל ₪20, ניתן לשינוי בהגדרות), או כשהפיצול משלים פריטים שאין באף סניף יחיד.
- **הסתרת רשתות** במסך ההגדרות: רשת מוסתרת לא מופיעה בחיפוש, בהשוואה ובפיצול.
- **ריצה לילית** כל יום ב-06:00 שעון ישראל, והכנה להעלאה לשרת עם HTTPS וגיבוי: ראו [DEPLOY.md](DEPLOY.md).
- **מעקב והתראות:** היסטוריית מחירים יומית למוצרים במעקב ולמוצרים שברשימות שמורות; דף מוצר עם גרף ומחיר יעד; מסך התראות; מייל יומי מרוכז. ראו "מעקב והתראות" למטה.
- **רשימות שמורות:** כמה רשימות, עם מעבר ביניהן במסך הרשימה.
- **מבצעים ומועדונים:** ראו "כללי המבצעים" למטה. המועדונים מסומנים במסך ההגדרות.
- **משתמשים:** כניסה עם חשבון Google; לכל משתמש רשימות, כתובות, מועדונים, הגדרות, מעקב והתראות משלו (ראו "משתמשים" למטה).

## עיצוב ומיתוג

הממשק מיושם לפי ערכת העיצוב "פראיירמטר 3.2" (המפרט והטוקנים המקוריים ב-`design/app-design-3.2/`; חבילת המיתוג הקודמת ב-`design/brand-kit/`):

- טוקני הצבע, הרדיוסים וסגנון הכפתורים מוגדרים ב-`web/app/globals.css`; הלוגו ב-`web/public/brand/logo.png` ואייקוני האפליקציה ב-`web/public/` וב-`web/app/`.
- צבעי המותג: טורקיז לפעולות, כתום לפעולה המרכזית של המסך (השוואת סניפים), ורוד להדגשה, סגול עמוק לטקסט ולמסגרות. צבעי הסטטוס (ירוק, ענבר, אדום, סגול למועדון, כחול לפיצול) נפרדים מהם.
- הגופן הוא Arial, בלי תלות חיצונית.
- מצב כהה: לפי המכשיר כברירת מחדל, או בחירה במסך ההגדרות.
- תג "הכי משתלם" ניתן רק לסל מלא ורענן (`web/lib/freshness.ts`, עם בדיקות). סל חלקי מציג כמה פריטים חסרים ואינו מקבל תג.
- רעננות מחיר מוצגת במילים ("עודכן לפני שעתיים"), עם חותמת זמן מדויקת, ולא בצבע בלבד.
- מחירים מבודדים משמאל לימין עם שם נגיש מלא.

## מבנה

| תיקייה | תוכן |
|---|---|
| `db/init/` | סכמת PostgreSQL (idempotent; רצה גם בכל הפעלת ingest) |
| `ingest/` | פייתון 3.12: הורדה, פענוח עם `il-supermarket-parser`, טעינה למסד, geocoding ו-worker |
| `web/` | Next.js + TypeScript + Tailwind |
| `docker-compose.yml`, `.env.example` | הרצה והגדרות |

## הרצה

```bash
cp .env.example .env        # ולשנות סיסמה
docker compose up -d --build
```

האפליקציה: http://localhost:3000

בהפעלה הראשונה ה-worker מוריד את רשימות הסניפים של כל הרשתות ומתחיל geocoding ברקע
(בקשה אחת בשנייה ל-Nominatim, כלומר כשעה-שעתיים לכל הארץ, פעם אחת בלבד).
אחר כך מוסיפים כתובת במסך ההגדרות, והמחירים של הסניפים שלידה נטענים מיד.

פקודות ידניות (ה-worker עושה את אותו הדבר לפי בקשות מהאפליקציה):

```bash
docker compose exec ingest python -m ingest status
docker compose exec ingest python -m ingest stores                 # רשימות סניפים, כל הרשתות
docker compose exec ingest python -m ingest prices                 # מחירים לסניפים ברדיוס
docker compose exec ingest python -m ingest prices --chain RAMI_LEVY --stores 1,39
docker compose exec ingest python -m ingest prices --all-stores    # כל הארץ
docker compose exec ingest python -m ingest address "בית" "הרצל 1, תל אביב" --radius 5
docker compose exec ingest python -m pytest -q tests
```

בדיקות חישוב הסל (מוצר שקיל, חלופות, פריט חסר, דירוג):

```bash
cd web && npm install && npm test
```

## מקורות הנתונים

| מקור | רשתות | איך מורידים |
|---|---|---|
| `prices.shufersal.co.il` | שופרסל | `il-supermarket-scraper` |
| `url.publishedprices.co.il` (Cerberus) | רמי לוי, יוחננוף, אושר עד, טיב טעם, דור אלון, יילו, קשת טעמים, פרש מרקט, סטופ מרקט, סאלח דבאח, סופר יודה, פוליצר | מוריד משלנו (`ingest/ingest/cerberus.py`) בממשק הווב: `GET /login`, `csrftoken` מתגית meta + עוגייה, `POST /login/user`, `/file/json/dir`, `/file/d/<שם>`. הספרייה ניגשת לרשתות האלה ב-FTP |
| `prices.carrefour.co.il`, `laibcatalog.co.il`, `shop.hazi-hinam.co.il`, `*.binaprojects.com`, `prices.super-pharm.co.il` ועוד | קרפור/יינות ביתן/מגה, ויקטורי, מחסני השוק, חצי חינם, סופר-פארם, גוד פארם ורשתות קטנות | `il-supermarket-scraper` |

רוב האתרים שבשורה השלישית חוסמים גישה מחוץ לישראל, ולכן את ה-ingest צריך להריץ משרת בישראל.
רשת שנכשלת מסומנת במסך ההגדרות ואינה עוצרת את השאר.

## איך הטעינה עובדת

1. **סניפים:** קובץ ה-Stores העדכני של כל רשת נטען לטבלת `stores`. עיר שמפורסמת כסמל יישוב של הלמ"ס מתורגמת לשם.
2. **Geocoding:** כל סניף מנוסה פעם אחת (עד שהכתובת שלו משתנה). כל שאילתה נשמרת ב-`geocode_cache`.
   אם הכתובת המלאה לא נמצאת, הסניף ממוקם לפי העיר (`geocode_precision = city`).
3. **מחירים ומבצעים:** לכל רשת מורידים את ה-PriceFull וה-PromoFull העדכניים של הסניפים שברדיוס כתובת שמורה
   (או של כל הסניפים כש-`INGEST_ALL_STORES=true`). כל קובץ נטען בטרנזקציה אחת ומחליף את מחירי הסניף.
   אם קובץ נכשל, המחירים הקודמים נשארים והסניף יסומן "לא עודכן".
4. כל ריצה נרשמת ב-`ingest_runs` (`ok` / `partial` / `failed`), וכל קובץ שנטען ב-`ingest_files`.

כללים שכבר מיושמים:

- פריט ברשימה הוא מוצר אחד או קבוצת חלופות; בכל סניף נלקחת החלופה הזולה (`web/lib/basket.ts`).
- התאמת מוצרים לפי ברקוד בלבד. קוד פנימי של רשת (`ItemType=0`) נשמר כמוצר של אותה רשת בלבד.
- `bIsWeighted=1`: המחיר נשמר ומוצג כמחיר לק״ג.
- ליד כל מחיר מוצג מתי עודכן הקובץ; קובץ ישן מ-`STALE_PRICE_HOURS` (36) שעות מסומן.

כתובת חדשה מאותרת מיד בתוך האפליקציה (`web/lib/geocode.ts`, אותו cache ואותו שירות כמו ה-ingest), כך שהסניפים
שבסביבה ומחירים שכבר נטענו מופיעים תוך שנייה או שתיים. ה-worker משלים ברקע מחירים לסניפים שעוד לא נטענו; אם שירות
האיתור לא עונה, הכתובת נשארת "ממתינה" וה-worker מאתר אותה.

## כללי המבצעים

החישוב נמצא ב-`web/lib/promos.ts` ו-`web/lib/basket.ts`, עם בדיקות ב-`web/tests/`.

- **סוג המבצע נקבע לפי השדות ולא לפי מספר ה-RewardType.** בקבצים שהרשתות מפרסמות בפועל המספרים אינם אחידים
  (למשל "2 ב-12" מופיע כ-RewardType 1 או 10, ומחיר מוזל כ-3 או 2). לכן:
  - `DiscountedPrice` נמוך ממחיר המדף: **מחיר מוזל** ליחידה (או לק״ג), מ-`MinQty` ומעלה.
  - `MinQty` של 2 ומעלה ו-`DiscountedPrice` גבוה ממחיר יחידה: **כמות במחיר קבוע** ("N ב-X"). יחידות עודפות במחיר מלא.
  - **הנחה על הפריט ה-N** אינה מקודדת בשדות אלא רק בתיאור. מזוהים שני ניסוחים חד-משמעיים: "1+1" ו"השני ב-X%".
- `MaxQty`: מעבר לכמות המרבית משלמים מחיר מלא. תאריכי תוקף נבדקים מול מועד החישוב.
- `ClubId` שונה מ-0: חל רק אם המועדון סומן בהגדרות; אחרת מוצג כ"חיסכון אפשרי לחברי מועדון".
- `MinPurchaseAmnt`: לא מחושב, רק מוצג כהערה. כך גם מבצע שמוגבל לימים/שעות או שבנוי מכמה קבוצות מוצרים.
- מבצעים שדורשים קופון (`AdditionalIsCoupon=1`) אינם נטענים.
- מבין כמה מבצעים על אותו מוצר נבחר הזול; מבצעים לא נצברים.
- "N ב-X" שחל על כמה מוצרים שונים: כמויות של שורות שונות בסל מצטרפות, בחישוב שמרני (היחידות הזולות נכנסות לחבילה).

## הוספה מחשבונית

במסך הרשימה, ״הוספה מחשבונית״: מצלמים או מעלים חשבונית (תמונה או PDF). הטקסט מזוהה בשרת עצמו, בלי שירות
חיצוני: Tesseract בעברית לתמונות ול-PDF סרוק, ו-`pdftotext` ל-PDF דיגיטלי (`web/lib/receipt.ts`). מפענח
(`web/lib/receipt-parse.ts`) מוציא מהטקסט את שורות המוצרים, עם ברקוד, כמות ומשקל, ומדלג על הנחות, פיקדון וסיכומים.
כל שורה מותאמת למוצר במאגר קודם כול לפי הקוד שהודפס לידה (ברקוד מלא, או קוד פנימי קצר של הרשת), ורק אם הקוד לא נמצא – לפי שם (`web/lib/receipt-match.ts`). מסך אישור מציג לכל
שורה את המוצר שזוהה ועוד מועמדים; התאמה לא בטוחה אינה מסומנת מראש. רק מה שאושר נכנס לרשימה הפעילה, בכמות
שבחשבונית. הזיהוי תלוי באיכות הצילום: חשבונית ישרה, מוארת, שממלאת את התמונה.

## משתמשים

- הכניסה עם חשבון Google (OAuth, בלי ספרייה חיצונית): `web/lib/google.ts`, `web/app/api/auth/google/`. הסשן הוא עוגייה
  חתומה (`web/lib/auth.ts`) שנבדקת ב-`web/middleware.ts`.
- הטבלאות `lists`, `addresses`, `tracked_products` ו-`alerts` נושאות `user_id`; חברות במועדונים, רשתות מוסתרות וסף
  הפיצול נשמרים ב-`user_clubs`, `user_hidden_chains` ו-`user_settings` (`db/init/006_users.sql`).
- כל שאילתה באפליקציה מוגבלת למשתמש המחובר (`web/lib/session.ts`, `web/lib/scope.ts`), וכל שינוי בפריט או בכתובת
  בודק שהם שייכים לו.
- קטלוג המוצרים, המחירים, המבצעים והיסטוריית המחירים משותפים לכולם. המחירים נטענים לסניפים שברדיוס של כל
  הכתובות של כל המשתמשים; ההתראות מחושבות לכל משתמש לפי הסניפים והרשתות שלו.
- ההגדרה בשרת: ראו "כניסה עם Google" ב-[DEPLOY.md](DEPLOY.md).


- `price_history` נשמר רק למוצרים במעקב ולמוצרים שברשימות שמורות, בסניפים שברדיוס, פעם ביום לכל סניף
  (היום הוא תאריך קובץ המחירים). ההיסטוריה מתעדכנת אחרי כל טעינת מחירים.
- **התראת שינוי:** המחיר הזול של המוצר ברשת השתנה ב-`ALERT_CHANGE_PCT` (10) אחוזים ומעלה לעומת היום הקודם.
  משווים רק סניפים שיש להם מחיר בשני הימים, והתראה אחת לכל מוצר ורשת ביום.
- **התראת מחיר יעד:** המחיר הזול מבין כל הרשתות ירד אל מחיר היעד או מתחתיו (ולא היה שם כבר אתמול). התראה אחת למוצר.
- **מייל יומי מרוכז:** `python -m ingest digest` שולח מייל אחד עם כל ההתראות שעוד לא נשלחו. כל משתמש מקבל את ההתראות שלו לכתובת ה-Gmail שלו. מוגדר ב-`SMTP_*`;
  בלי הגדרה לא נשלח מייל, וההתראות מופיעות רק באפליקציה. המייל נשלח אוטומטית בסוף הריצה הלילית.

## הערות

- סריקת ברקוד דורשת HTTPS (או localhost), כי הדפדפן לא נותן גישה למצלמה באתר לא מאובטח.

- גרסאות הספריות: `il-supermarket-scraper==1.1.0`, `il-supermarket-parser==1.0.16`. ה-scraper דורש Python קטן מ-3.13.
- אפשר להחליף את שירות ה-geocoding ב-`GEOCODER_URL` (כל שירות תואם Nominatim).
